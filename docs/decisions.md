# Decisions log

| Date | Decision | Why |
| --- | --- | --- |
| 7 Oct 2026 | Domain is gurugramvisionforum.org; gurgaonvisionforum.org redirects to it | Matches the email domain and the city's legal name. Both were available on 7 Oct 2026 and still need to be bought. |
| 7 Oct 2026 | Vercel + Supabase instead of Cloudflare Pages/Workers + Freshdesk | The owner already runs both. No per-seat cost, data stays in Postgres, public report pages and open data become simple. The triage inbox and SLA automation are built here instead of configured in Freshdesk. |
| 7 Oct 2026 | Server generates the report reference | One source of truth. The browser only falls back to a local reference when the API is unreachable, and says so. |
| 7 Oct 2026 | Status lookup needs reference plus last four digits of the mobile | Launch guide appendix B deliverable 3; returns stage and dates only. |
| 7 Oct 2026 | Dashboard publishes nothing until 50 reports | HANDOFF.md section 1, rule 4. The endpoint returns the running total only. Superseded 8 Oct 2026: counts are public from the first report (see below). |
| 7 Oct 2026 | Volunteer desk signs in with email and password, accounts created by the coordinator | No email sending needed at launch, so no SMTP or redirect-URL setup; Supabase's built-in mailer is rate-limited. Magic links can come later with custom SMTP. |
| 7 Oct 2026 | The desk is a separate static page (`triage.html`), not a route in the public app | Keeps the public bundle and its Hindi dictionary unchanged, and keeps reporter details out of the public app's code paths. |
| 7 Oct 2026 | The desk lives inside the main site at `#/desk` | Owner's ask: move freely between public pages and the desk. The earlier separate page was a privacy convenience, not a requirement. |
| 7 Oct 2026 | Ward volunteers: one lead and one support per ward, scoped to their wards; coordinators and owners see all | Owner's operating model. Assignments are data (`ward_volunteers`), changed from the Team tab. |
| 7 Oct 2026 | Maps start on OpenStreetMap tiles and Nominatim; Google Geocoding switches in when a key is provided | Works today without a billing account. Google is better for Indian addresses and is a one-line environment change. |
| 7 Oct 2026 | Ward boundaries come from GMDA's GIS file, not an API | No public API exists for MCG wards. The database and form are ready for the file; until then wards come from the resident, the sector table and the desk. |
| 7 Oct 2026 | All API routes go through one serverless function (`api/index.js` behind a `/api/:path*` rewrite; a bracketed catch-all file only matched one path segment on Vercel) | The Hobby plan allows 12 functions per deployment; the desk and map work took us to 13 and every deploy failed. One router removes the ceiling and keeps new routes a one-line change. |
| 7 Oct 2026 | Every issue type lists what its official portal needs, collected at report time and checked at the desk | Owner's ask: the Forum must be able to file on the resident's behalf. Requirements are data (`GVF.FILING`, `issue_types.filing`), answers go to `reports.extra`, files to `report-photos` via one-hour upload tokens and signed URLs, and the desk shows a checklist with what is missing and a ready message to ask for it. The browser never gets a storage key. |
| 7 Oct 2026 | Hindi for data-driven content is a string table keyed by the English text (`GVF.HS`, `hs()`), not parallel Hindi fields on every record | One mechanism covers issue types, portals, charters, roles, wards, areas, filing fields and interface strings in app.js; English stays the single source of truth and the value sent to the API. Councillor names and parties are transliterated; agency acronyms stay in Latin script. |
| 8 Oct 2026 | Notifications are queued in an `outbox` table by a database trigger and sent by the daily cron through Resend | One path for every stage change whatever moved the report; nothing emails from inside a request; the queue survives a missing key until the owner sets one. |
| 8 Oct 2026 | Public report pages and map read an anonymised view with coordinates rounded to 3 decimals | Residents can share and follow a report without the Forum ever exposing a name, number, description, exact spot, ticket or file. |
| 8 Oct 2026 | Inbound WhatsApp and helpline calls create reports as "Something else" for the desk to map | The channels can go live the day Meta or Exotel approve them with no code change; mapping by a volunteer beats guessing the issue type from a message. |
| 8 Oct 2026 | Visitor registration gate (after 90 s or 2 pages) in a soft mode by default: name and mobile required, the rest optional, "Not now" for a week; a hard mode is one setting away | Owner wants to know every user but chose reach over compulsion after the DPDP memo; the gate is first-party only and every reporter is registered anyway. |
| 8 Oct 2026 | Team content lives in `posts` and is edited from the desk; social posts are linked, not embedded | No deploy for daily news; embedding X/Facebook/Instagram scripts would load third-party trackers on every page, against the privacy notice. |
| 8 Oct 2026 | Official news is collected server-side from the bodies' own pages (RSS or HTML), never from third-party aggregators | Every item links to the official page; sources are data (`data/news-sources.json`). |
| 8 Oct 2026 | Real URLs are Vercel rewrites to the same single page | Shareable, unfurling links without a build step; the app stays hash-routed inside. |
| 8 Oct 2026 | Four staff roles (owner, coordinator, triage, content), enforced per endpoint in the API; the desk only mirrors them | Owner's ask: owners see all, ward volunteers only their wards, the content team only content. A hidden tab is not a gate; the handlers check the role list. |
| 8 Oct 2026 | Content auto-translates between English and Hindi through the free-first AI chain, filling only empty fields | The site is fully bilingual and the team writes in one language; the model fills the other, a person still reads it before publishing. |
| 8 Oct 2026 | The Gurugram pulse reads Reddit's public JSON and Google News RSS; not X/Twitter or Quora, and not the Forum's own reports (owner's decision, 8 Oct: the pulse is about the city's public discussion; what residents report to the Forum stays with the team, shown publicly only as the anonymised report page and counts) | X has no free API and Quora's terms forbid scraping. Only titles, snippets, links and dates are stored, never a poster's name or handle; the public page shows counts and links. |
| 8 Oct 2026 | News sources are probed weekly from GitHub Actions and switched on or off in `data/news-sources.json` with the reason recorded | The development sandbox cannot reach government hosts; several official sites answer only Indian IPs, render with JavaScript or have broken TLS. Keeping the reason next to the entry stops the same URLs being retried blindly. |
| 8 Oct 2026 | Search visibility comes from server-rendered pages built from the Forum's own data (issue guides, ward pages, blog, in English and Hindi) plus one automated weekly round-up with a review window and a disclosure line; no programmatic issue × sector pages | Google's scaled-content and doorway policies penalise pages that exist only to catch queries; pages carrying unique real data and one data-driven article a week are what its guidance calls people-first. See docs/growth-and-seo-research.md. |
| 8 Oct 2026 | Search engines are told about changes through the sitemap and IndexNow only | Google's Indexing API covers job postings and livestreams only and its sitemap ping was retired; IndexNow (Bing, Yandex, Naver, Seznam) is free and official. |
| 8 Oct 2026 | Installable web app, no native app and no push notifications for now | The PWA gives the home-screen icon and offline shell at no cost; web push opt-in runs under 10 % and email plus WhatsApp already carry the digest. |
| 8 Oct 2026 | Domains registered on Vercel: gurugramvisionforum.org (primary) and gurgaonvisionforum.com (the spelling on the deck; the .com was what the owner bought); the second and both www hosts redirect to the first | Registrar and DNS in the same place as hosting, so the project attaches with no record copying and TXT records for Search Console or email are one screen away. |
| 8 Oct 2026 | Reports are confidential: counts only in public, never one report | Owner's decision, non-negotiable. What residents report stays with the team; the public sees how many reports a ward has, by issue and by stage (dashboard, ward pages, Wards page), which keeps the team accountable without exposing anyone. The public report page, map, follow-by-email and the `public_reports` view were removed; `/r/<ref>` and `/map` show a notice. The reporter's own track view (reference + last 4 digits) stays. |
| 8 Oct 2026 | HSTS and a Content-Security-Policy on every response | Hardening after the confidentiality decision: scripts only from the site and unpkg (MapLibre), connections only to the API, Supabase storage (uploads) and OSM tiles, no framing. The same CSP is a meta tag in `index.html` so the smoke test catches a violation before deploy. |
| 8 Oct 2026 | No public contact details: the forms are the only channel | Owner's decision. The email address, phone number and project lead's name are gone from the site (footer, About, privacy, accessibility, gate consent, SEO pages, Organization JSON-LD, round-up disclosure). Report and Join forms are the official channels; the offline fallbacks offer "Send again" and copy instead of an email. Data-subject requests under the DPDP Act go through the Join form's note. |
| 8 Oct 2026 | Join requests get a desk tab and a coordinator mail | Owner asked how the team sees people who sign up. `joins` gains status, notes, handled_by, updated_at; the desk's Join requests tab (owner, coordinator) works them; each new request queues an outbox mail naming the person and role only. |
| 8 Oct 2026 | Automated upkeep: API in Mumbai, every link checked nightly at 00:00 IST, live "Links verified" date, uptime probe | Owner's ask: links must never be stale and the site never silently down. `regions: ["bom1"]` makes India-only government hosts reachable from the cron; `/api/dashboard` carries the last check so the footer date is live; `uptime.yml` (every 30 min) and the nightly `check-health.mjs` open GitHub issues on failure. A free external monitor with SMS is recommended on top. |
| 8 Oct 2026 | WhatsApp: build on Meta's Cloud API directly, no middleman | See docs/desk-and-whatsapp-research.md: Meta charges per message (about ₹0.115 per utility message, service replies free up to 1,000 a month); BSPs add ₹999 to ₹9,500 a month for an inbox the desk already is. Glific or Gupshup only if Meta verification stalls. |
| 8 Oct 2026 | Coordinators over ward clusters, a roster dashboard, a desk inbox, an ageing tracker and a daily brief | Owner's ask. Ward roles are coordinator / main lead / support lead, assigned per person from one screen; mail reaching the Forum lands in the desk Inbox (inbound-email webhook) so nothing waits in a mailbox; Performance shows ageing per ward and activity per person; the cron briefs owners and coordinators every morning by email and owners on WhatsApp (template, once Meta is set up). |
| 8 Oct 2026 | Newsletter list mirrored to Resend contacts; the Forum stays the record | Owner's ask: see the weekly-digest sign-ups and manage subscribe/unsubscribe automatically through a free or cheapest tool with rich features. Resend is already the site's mail provider and its marketing side is free to 1,000 contacts (unlimited Broadcasts, editor, unsubscribe handling, webhooks), so no second account, no second list and no cost. Double opt-in and the Forum's own stop link stay; both sides stay in step through `lib/audience.js` and the contact webhooks. Brevo (free, 300/day) or Kit (free to 10,000) only if the list outgrows 1,000. |
